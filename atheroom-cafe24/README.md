# 엣더룸 · 상품 작업실

사진을 올리고, 기존 쇼핑몰에서 승인한 형식으로 상품 초안을 준비하는 웹 앱입니다.

**현재 제공 상태:** 로컬에서 실행 가능한 MVP 소스와 체험 모드, 자동 테스트, PostgreSQL 스키마·마이그레이션, 배포 구성. **실제 카페24·OpenAI·S3/R2 연결과 운영 배포는 아직 검증하지 않았습니다.** 운영용 연결 정보와 실제 표본이 필요합니다.

## 먼저 화면 열기

현재 작업 중 열어둔 화면: [로컬 상품 작업실](http://127.0.0.1:3011)

서버가 종료되면 이 폴더의 **작업실-열기.command**를 실행하세요. 처음에는 필요한 프로그램 묶음을 설치하므로 시간이 걸릴 수 있습니다. Python 3.12 이상과 Node.js 22 이상이 필요합니다. macOS가 실행 파일을 차단하면 터미널에서 프로젝트 폴더로 이동해 `bash start-local.sh`로 실행할 수 있습니다.

1. **체험 작업실 열기**를 누릅니다.
2. **체험 쇼핑몰 연결하기**를 누릅니다.
3. 분석된 형식을 미리보고 **이 형식 사용하기**를 누릅니다.
4. 새 상품을 만들고 사진을 올립니다.
5. **체험 초안 만들기**를 누른 뒤 상품명·설명·금액·소재·사이즈와 사진 용도를 직접 확인합니다.
6. 각 사진 아래에서 용도를 선택합니다. 대표 사진은 맨 앞에 자동으로 사용됩니다.
7. 상품군이 맞는지 확인하고 **이 상품군으로 확인하고 저장**을 누릅니다.
8. 등록 전 확인에 남은 필수 항목을 해결합니다. 각 항목을 누르면 해당 사진이나 입력란으로 이동합니다.
9. 사진 수·설명 길이가 기존 형식과 달라도 괜찮다면 진행 동의에 체크하고 **검수 완료하기**를 누릅니다. 검수 완료 안내가 나오면 **체험 등록하기**가 활성화됩니다.

체험용 기존 상품과 문구는 검증을 위한 합성 데이터입니다. 실제 엣더룸 상품을 분석한 결과가 아닙니다. 체험 모드에서는 사진의 내용을 AI가 판단하지 않으며 실제 쇼핑몰에도 등록되지 않습니다.

## 확인한 상세페이지 순서

메인 사진 → 상품 설명·소재·사이즈 안내 → 착용 사진 ① → 제품 사진 ① → 착용 사진 ② → 제품 사진 ② → 착용 사진 ③ → 제품 사진(디테일/클로즈업) → 배송 안내 → 교환/반품 안내.

대표로 지정한 사진을 맨 앞의 메인 사진으로 사용하며, 본문에 다시 중복 배치하지 않습니다. 같은 용도의 사진은 지정한 순서대로 첫째·둘째·셋째 위치를 채웁니다. 추가 사진은 마지막 동일 용도 영역에 이어집니다. 체험 화면에 이 순서의 새 형식 미리보기를 저장했습니다. 배송·교환/반품의 실제 문구는 쇼핑몰에서 확인한 내용을 사용해야 합니다.

사진 수·설명 길이 차이에 대한 동의는 사진 용도와 상품군의 필수 확인을 대신하지 않습니다. 초안을 다시 생성해도 이미 확인한 사진 용도·순서와 상품군은 유지합니다.

## 포함된 기능

- 카페24 승인 연결, 암호화 저장, 만료 전 갱신
- 생성일 기준 최근 30개 분석, 실패 상품 제외, 상품군 표본 보충
- HTML 정제·구조 비교·반복 스타일 선택
- 전체 형식과 상품군별 형식 저장, 미리보기 승인, 버전 비교·보관
- 여러 사진 업로드, 대표 선택, 순서 변경, 용도·신뢰도 확인
- 구조화된 AI 결과, 확인된 사실만 입력하는 상품 편집
- 저장된 형식으로 상세페이지 렌더링, 미리보기와 검수
- 기존 상품 비교, 중복 경고, 등록 체크포인트·부분 실패·재시도
- 운영 설정과 작업 목록

## 설치 담당자용 — PostgreSQL 기반 실행

Docker와 Docker Compose가 있는 환경에서 실행합니다.

```bash
cp .env.example .env
cp backend/.env.example backend/.env
# 루트 .env의 POSTGRES_PASSWORD를 충분히 긴 무작위 값으로 변경합니다.
# backend/.env의 DATABASE_URL은 Compose가 내부 주소로 덮어씁니다.
docker compose up --build
```

[작업실](http://localhost:3000)을 엽니다. 처음은 DEMO_MODE=true를 유지해 기능을 확인할 수 있습니다. 실연결을 위해서는 다음을 배포 담당자가 준비해야 합니다.

- 카페24 앱 등록, 지정 쇼핑몰, 앱 자격정보, 정확히 일치하는 승인 반환 주소
- OpenAI 사용 가능한 프로젝트 키
- 비공개 S3 또는 R2 버킷과 접근 권한
- 운영자 이메일·비밀번호 해시와 토큰 암호화 키
- HTTPS 도메인과 프록시

`backend` 폴더에서 `python -m app.provision`을 실행해 암호화 키와 비밀번호 해시를 생성합니다. 생성값은 서버 비밀 설정에만 보관합니다. 카페24 비밀번호는 이 앱에 저장하지 않습니다.

운영에서는 APP_ENV=production, DEMO_MODE=false, STORAGE_BACKEND=s3와 HTTPS 주소를 설정합니다. 기존 DB를 백업한 뒤 `alembic upgrade head`를 적용합니다. 운영에서 SQLite나 체험 로그인으로 시작하는 설정은 서버가 거부합니다. V1은 단일 운영자·단일 쇼핑몰, 원 단위 일반 판매가 방식 기준입니다.

### 요청 크기와 대기 시간

최대 업로드는 20 × 5MB입니다. 프록시 업로드 한도를 110MB 이상으로 설정하세요. 최초 상품 비교 인덱스 구축과 이미지 업로드는 영속 worker에서 진행하며 운영 화면은 작업 결과를 조회합니다. 원격 호출 시간은 데이터 양에 따라 길어질 수 있습니다. 운영자 로그인 시도 제한은 V1 단일 API 프로세스 메모리 기준이므로 여러 API 인스턴스로 확장할 때 중앙 제한 저장소로 옮겨야 합니다.

### 로컬 테스트

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock.txt
pytest -q
cd ../frontend
npm ci
npm run typecheck
npm run build
```

외부 키가 없어도 테스트를 실행할 수 있습니다. 테스트는 실제 상품을 만들지 않습니다. `requirements.lock.txt`와 `package-lock.json`에 검증 시 설치된 버전을 기록했습니다.

### 운영 전 반드시 남은 확인

실제 PostgreSQL에서 마이그레이션·동시 승인·동시 등록을 확인하고, 실제 쇼핑몰 표본으로 고정 문구·배치·상품군·문체를 검수해야 합니다. 카페24 상품 1개를 비진열·판매 중지 상태로 등록해 각 응답 필드와 이미지 반영 결과를 확인하세요. OpenAI 실제 응답 품질·비용, S3/R2 권한과 보관 정책도 운영 환경에서 점검해야 합니다.

환경변수 파일, 데이터베이스 파일, 사용자 업로드와 인증 정보는 배포 이미지나 소스 공유 파일에 포함하지 마세요.
