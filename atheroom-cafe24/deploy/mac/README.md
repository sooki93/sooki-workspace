# 맥북과 Vercel로 사용하는 작업실

온라인 저장소나 유료 AI API를 사용하지 않습니다. Vercel은 화면과 맥북 연결을 맡고, 상품·사진·카페24 연결 정보는 맥북에 저장합니다. AI는 이 맥의 ChatGPT 로그인으로 Codex를 실행합니다.

## 매번 사용하는 순서

1. 맥북을 켜고 인터넷에 연결합니다.
2. 프로젝트의 `온라인 작업실 열기.command`를 더블 클릭합니다.
3. 연결 반영이 끝나면 온라인 작업실이 열립니다. 처음 연결에는 배포 시간이 필요합니다.
4. 작업실 계정으로 로그인해 상품을 준비합니다. 도우미 창은 열어둡니다.
5. 사용을 마치고 진행 중인 작업이 없으면 도우미 창에서 Control+C로 종료합니다.

맥북이 꺼지거나 잠자기 상태이면 조회·저장·AI 작업·등록이 중단됩니다. 화면에 입력만 하고 저장하지 않은 내용은 보관되지 않습니다. 저장된 대기 요청은 도우미가 다시 실행되면 처리합니다. 처리 도중 중단된 작업은 상태를 확인하고 다시 시작해야 합니다.

## 연결 방식과 제한

- 사진 업로드는 로그인 후 발급한 10분짜리 전송 승인으로 맥북에 직접 보냅니다. 승인에는 특정 상품과 선택한 사진의 해시가 묶여 있으며, 일반 상품 조회·수정 권한은 부여하지 않습니다. 한 장당 5MB, 최대 20장 제한은 유지합니다.
- 외부 통로는 Cloudflare Quick Tunnel을 사용합니다. 재실행 시 주소가 달라지므로 도우미가 Vercel의 서버 설정을 갱신하고 재배포합니다. 사용자가 접속하는 Vercel 주소는 같습니다.
- Quick Tunnel은 가용성을 보장하지 않는 개발·시험용 연결입니다. 개인 작업실에서 사용할 수 있는 임시 구성으로, 매장 업무에 상시 가용성이 필요하면 별도의 고정 터널을 구성해야 합니다.
- Vercel의 기존 요금제 사용량은 발생합니다. 새 데이터베이스 구독이나 유료 AI API는 연결하지 않습니다.
- 처리된 사진과 데이터베이스는 `.local-cache/online` 아래에 있습니다. 이 폴더는 GitHub에 업로드되지 않습니다. 맥북을 바꾸기 전에는 안전한 별도 위치에 백업해야 합니다.
- Codex 사용 한도에 도달하면 AI 작업은 대기 상태가 됩니다. 한도가 회복된 후 해당 작업에서 다시 시작하세요.

## 최초 설정(개발자용)

`.local-cache/online/config.json`은 사용자 맥에서만 만듭니다. 파일/디렉터리 권한은 600/700을 사용합니다. 설정에는 `python`, `npm`, `cloudflared`, `vercel_auth`, `scope`, `project_id`, `repo_id`, `url`, `port`, `env`가 필요합니다. `env`에는 전용 SQLite 연결, 로컬 사진 경로, 운영자 이메일·비밀번호 해시, 토큰 암호화 키, 임의의 32자 이상 `BRIDGE_TOKEN`, HTTPS 화면 주소, 카페24 앱 설정을 넣습니다. 실제 키와 비밀번호를 저장소에 넣지 마세요.

API는 `127.0.0.1`에만 바인딩하고 일반 API 요청에 연결 비밀값을 검사합니다. 서명된 직접 업로드와 그 CORS 요청에는 별도의 티켓·출처 검증을 적용합니다. 일반 API의 연결 비밀값은 Vercel의 서버 전용 환경 변수 `STUDIO_BRIDGE_TOKEN`과 같아야 합니다. 브라우저에는 전달하지 않습니다. 개인 작업실 모드는 실제 등록 모드이며 체험 데이터와 분리해야 합니다.

최초 데이터 이전은 원본 SQLite 백업을 만든 후 진행하세요. 기존 운영 DB의 카페24 토큰을 복제한 경우, 토큰 갱신 충돌을 막기 위해 이전 복제본으로 운영하지 마세요. 카페24 재연결을 사용하려면 개발자센터에 최종 Vercel 주소의 `/api/cafe24/callback`을 허용해야 합니다.

현재 작업 기준은 [프로젝트 AGENTS.md](../../AGENTS.md)입니다. Vercel 작업에는 MCP/API/CLI를 사용하고 Computer Use로 화면을 조작하지 않습니다.

- 프로젝트 ID `prj_awPmVd08ot9P1GObc7oG2CwGVz4f`, 팀 ID `team_EfNYcsT2ILanbPQZ8I3taSPa`는 확인용 공개 식별자다. 실제 변경 전 프로젝트 이름·rootDirectory·Git 연결을 함께 조회한다.
- 런처는 Vercel CLI 59.15.1을 통한 API 연결을 사용한다. 환경 변수는 각 객체를 `/v10/projects/{id}/env?upsert=true`에 보내고 배포는 `/v13/deployments`로 생성한다. 환경 변수 배열 전송은 이 작업에서 실패했으므로 검증 없이 되돌리지 않는다.

GitHub 푸시만으로 실행 중인 Mac API/worker가 갱신되지는 않습니다. API·환경 설정 변경은 작업이 끝난 뒤 도우미를 정상 종료하고 재실행해야 합니다. 이때 새 터널 주소로 Vercel 배포가 완료됐는지 확인합니다.

새 Mac에서 저장소를 clone하는 것만으로 운영 데이터와 인증 설정은 복원되지 않습니다. 기존 설정의 실행 파일 경로를 확인하고 DB·사진·암호화 키를 안전하게 이전해야 합니다. SQLite WAL을 고려한 일관된 백업을 사용하세요.

## 장애 확인 순서

1. Mac 전원·잠자기·인터넷과 도우미 실행 상태를 확인한다.
2. 비밀값을 출력하지 않고 API/worker/터널 로그와 프로세스를 확인한다. 현재 터널과 Vercel production 연결 설정이 일치하는지 확인한다.
3. 화면 연결, 앱 로그인, worker 상태를 확인한다. 로그인 확인만 성공했다고 실제 AI 호출까지 통과했다고 보고하지 않는다.
4. 엑박이면 현재 이미지 ID, 소유권, 응답 상태/형식과 실제 파일 존재를 확인한다. 무작정 새 파일 업로드나 DB 초기화를 하지 않는다.
5. 등록 실패면 대상 상품 번호와 단계 결과부터 읽는다. 완료 단계와 생성 불명확 상태를 보존한다.

## 백업과 이전

DB 변경 전 안전한 백업을 만든다. SQLite WAL이 활성일 때 DB 파일 하나만 무조건 복사하지 말고 SQLite backup API 등 일관된 백업을 사용한다. 사진 저장소와 복호화에 필요한 암호화 키·설정을 함께 안전하게 보관한다. 새 Mac에서 설정 경로·권한과 의존성을 확인하고 마이그레이션한다. 이전 토큰 복제본을 동시에 운영하지 않는다.

Cafe24 재연결에는 개발자 앱의 허용 반환 주소가 `https://atheroom-cafe24.vercel.app/api/cafe24/callback`과 정확히 일치해야 한다. 기존 토큰으로 조회가 되는 것과 새 주소의 OAuth 재연결 검증은 별개다.
