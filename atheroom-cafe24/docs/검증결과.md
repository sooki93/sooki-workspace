## 자동 테스트 범위

- 호스팅 PostgreSQL URL을 설치된 드라이버로 변환하면서 인코딩된 암호·옵션 유지, SQLite URL 유지
- S3 주소 지정 설정에 따라 버킷을 호스트에 포함한 서명 URL 생성, 잘못된 설정 거부 (실제 저장소 호출 없음)
- 생성일 기준 recent 조회 파라미터 고정, 수정일 배제
- 암호화된 연결 정보·운영자 비밀번호 검증
- OAuth state 검증, 취소 시 소비, 재사용 차단
- 위험 HTML·이벤트·실행 주소·CSS 제거
- 상품 고유 값이 구조 비교 및 신규 렌더링에 섞이지 않는지 검사
- 단발 스타일 배제, stable 선택, 표본 부족 처리
- 분석 30개 중 3개 실패 시 27개 DRAFT 생성
- ACTIVE 1개 DB 제약과 새 버전 승인 시 이전 버전 보관
- 실제 이미지 디코딩, 크기 제한, SHA-256·pHash
- AI 결과 스키마의 허용되지 않은 상업 정보 필드 거부
- 텍스트 삽입 escaping과 템플릿 재평가 차단
- 일부 이미지 업로드 실패 후 성공 단계 생략·재시도
- 기본 상품 생성 결과 불명확 시 자동 재생성 방지
- 유사 이미지·상품명 비교
- 원격 이미지 조회 시 내부망 주소 차단
- 체험 연결 → 승인 → 업로드 → 생성 → 필수 정보 입력 → 사진 확인 → 검수 → 등록 → 재분석 → 새 버전 승인
- 타 사용자 상품 접근과 다른 Origin의 상태 변경 요청 차단

SQLite 및 실제 PostgreSQL의 독립 테스트 환경과 실제 파일 디코딩을 사용했다. AI 및 카페24 전송은 테스트 대역으로 수행했다. 외부 상품을 생성하지 않았다. 테스트 실행 중 테스트 클라이언트 라이브러리의 향후 변경 안내 2개가 발생했으며 테스트 실패는 없었다.

## 실행하지 못한 검증과 이유

- **배포 구성 그대로의 Docker 실행:** 로컬 PostgreSQL 18.4 검증은 완료했다. Compose에 지정된 PostgreSQL 17 컨테이너와 외부 배포 환경은 아직 검증하지 않았다.
- **실제 Cafe24 OAuth·토큰 갱신·상품/이미지 등록:** 쇼핑몰 앱 자격정보와 사용자 승인이 제공되지 않았다. 공식 문서에 맞춰 어댑터를 구현했으며 실제 응답 필드·권한·쇼핑몰 설정별 차이는 실계정으로 확인해야 한다.
- **실제 OpenAI 이미지 분석:** 운영용 키가 없어 모델을 호출하지 않았다. 출력 스키마·검증·실패 처리는 구현되어 있지만 실상품의 분류 정확도와 글 품질은 측정하지 않았다.
- **실제 S3/R2 업로드:** 저장소와 자격정보가 제공되지 않았다. 로컬 저장소 경로만 실행했다.
- **다른 브라우저·기기:** Codex 내장 브라우저의 데스크톱 화면에서 확인했다. 다른 브라우저와 모바일 기기 조합 전체는 검증하지 않았다.
- **외부 배포:** 대상 서버·도메인·운영 계정이 없어 수행하지 않았다.

## V1의 구체적인 범위와 제한

1. 단일 배포는 운영자 1명과 쇼핑몰 1개를 지원한다. 회원 가입·초대·다중 조직 관리 화면은 없다.
2. 원 단위 일반 판매가 방식 쇼핑몰을 대상으로 한다. 세금 제외 방식은 금액을 임의 변환하지 않고 차단한다.
3. 기존 HTML의 안전한 태그·스타일을 보존한다. 외부 스타일시트·스크립트·이미지로만 구성된 안내의 의미를 완전히 재현하지는 못한다. 실제 원본과의 미리보기 비교가 필요하다.
4. 구조 유사도·고정 문구·상품군·이미지 역할은 휴리스틱과 AI 의미 분석을 결합한다. 실제 쇼핑몰 표본을 통한 오분류·잘못된 고정 문구 검증이 필요하다. 픽셀 단위 동일함은 보장하지 않는다.
5. 추가 이미지 지정은 하나의 교체 요청 단위다. 사진 파일 업로드는 개별 재시도하지만 추가 목록 지정 실패 시 그 목록 지정 요청 전체를 다시 보낸다.
6. 기존 상품 이미지 중복 비교는 대표 이미지 인덱스 기준이다. 기존 상세페이지의 모든 이미지 파일을 전체 수집하지 않는다. 사진 수집 실패가 있으면 비교 불완전 안내 후 사용자가 확인해야 한다.
7. 상품 생성 결과를 잃고 재조회에서도 찾지 못하면 중복 방지를 위해 자동 재생성을 중단한다. 지속적인 불명확 상태는 쇼핑몰 확인 후 운영 담당자의 기록 복구가 필요하다.
8. 기존 패턴에 사진 역할이 없으면 해당 역할을 임의 위치에 추가하지 않는다. 사용자가 사진 용도 또는 참고 형식을 바꿔야 한다.
9. 원본 내용을 여러 텍스트 슬롯에 나누어 사용한 구조에서는 새 설명을 최초 해당 슬롯에 넣고 나머지 변수 슬롯은 비운다. 복잡한 편집기 특유의 문단 배치를 완벽하게 복제하려면 해당 쇼핑몰용 렌더링 규칙을 확장해야 한다.

실서비스 운영 완료로 간주하기 전에 위 실연결 검증을 완료해야 한다.

## 등록 전 확인 안내 수정 검증

사진별 미분류·미확인·배치할 수 없는 용도와 상품군 확인을 개별 필수 항목으로 반환하며, 화면에서 해당 입력 위치로 이동할 수 있도록 했다. 사진 수·설명 길이 차이는 별도 동의로 구분했다. 상품군 값을 바꾸지 않아도 확인하여 저장할 수 있고, 검수 버튼이 비활성화된 이유와 검수 성공·실패를 버튼 근처에 표시한다. 대표 사진에 전용 영역이 있으면 별도 용도 선택을 요구하지 않는다.

추가 테스트 4개로 차이 동의만으로 필수 확인을 우회할 수 없는 점, 상품군을 그대로 확인하고 사진 수 차이에 동의하면 검수 및 등록 요청이 가능한 점, 미분류 사진 확인 차단, 재생성 시 확인된 사진 용도·순서·상품군 보존을 검증했다. 총 28개 테스트와 TypeScript 검사·production build가 통과했다. 로컬 작업실의 저장된 상품을 읽어 새 필수 항목 응답을 확인했으며 사용자 상품의 분류·검수·등록 상태는 변경하지 않았다. 브라우저 조작·시각 검증은 실행하지 않았다.

## 실제 화면 점검 후 보완

기존 사용자 상품과 분리된 시험 데이터로 직접 조작했다. 시험 사진은 번호를 표시한 합성 이미지이며, 실제 AI나 카페24 호출은 사용하지 않았다.

확인한 흐름:

- 체험 로그인 → 쇼핑몰 연결 → 분석 결과 승인 → 새 상품 생성
- 사진 8장 업로드·용도 선택·상품 정보 저장 → 미리보기 사진 8장 표시 → 검수 → 체험 등록 완료
- 사진 2장만 사용하고 사진 수 차이를 허용 → 검수 → 중복 경고 취소 → 다시 요청·확인 후 체험 등록 완료
- 필수 항목이 남아 있을 때 차이 확인만 체크해도 검수는 비활성화 유지
- 필수 사진 항목을 누르면 해당 용도 선택란으로 이동·포커스
- 새 상품 주소 갱신, 메뉴 이동 시 상품·운영 설정 저장, 새로고침 후 복원
- 상품 정보를 먼저 작성한 상태에서 사진 업로드 → 초안 생성 후 직접 작성한 상품명·설명 유지
- 잘못된 금액 저장 시 오류 표시와 기존 저장 값 유지
- 새 형식 분석은 검토 상태로 남음 → 승인 후 이전 형식의 상품에 재적용 안내 → 다시 검수하면 등록 가능

발견하여 수정한 문제:

1. 사진 데이터가 준비되기 전에 미리보기 프레임을 만들면 사진이 깨져 보였다. 사진을 준비한 뒤 프레임을 만들고, 불러오기 실패 시 재시도 버튼을 제공한다.
2. 새 상품을 만든 뒤에도 이전 상품 주소가 남았다. 생성 즉시 새 작업 주소를 저장한다.
3. 긴 미리보기·검수 영역이 화면에 고정되어 등록 버튼까지 일반 스크롤로 접근하기 어려웠다. 페이지 흐름에 따라 스크롤되도록 수정했다.
4. 저장을 기다리는 동안 파일 선택 목록이 비워져 업로드가 실패했다. 선택한 파일을 먼저 복사해 보관한다.
5. 메뉴 이동·새 상품 생성 시 미저장 입력이 사라질 수 있었다. 이동 전에 저장하고 새로고침·탭 닫기에는 미저장 경고를 추가했다. 닫기 경고는 코드에 반영했으며 실제 브라우저 종료는 수행하지 않았다.
6. 재생성으로 수동 작성 내용이 덮어써졌다. 수정한 필드를 기록해 보존하고, 사용자가 비운 필드는 재생성 대상으로 돌린다. 기존 초안은 이전 생성 결과와 비교하여 보존한다.
7. 형식 변경 후 재적용 버튼이 보이지 않는 경우가 있었다. 차이 경고 유무와 관계없이 재적용·재검수 경로를 제공한다.
8. 체험 상태에서 실제 카페24 연결 경로에 직접 접근할 수 있었다. 연결·반환·전송과 작업 실행에서 실행 모드 경계를 확인한다.

## PostgreSQL 추가 검증

로컬 PostgreSQL 18.4에서 실제 Alembic 마이그레이션을 적용했다. 매 테스트마다 고유한 임시 스키마를 만들고 해당 스키마만 정리한다. 실제 DB를 사용하는 전체 운영자 API 흐름과 서로 다른 연결의 동시 형식 승인 후 ACTIVE 한 개 유지, 추가 ACTIVE 삽입 거부를 확인했다. AI 및 카페24는 이 검사에서도 테스트 대역이다.

실행: 테스트용 PostgreSQL 주소를 `TEST_POSTGRES_URL`에 설정하고 `pytest -q`를 실행한다. 주소가 없으면 PostgreSQL 전용 2개 검사는 건너뛰며 나머지 33개를 실행한다.

## 상세페이지 문구와 등록 조건 분리

상품명·설명·SEO의 소재·치수·인증 단어를 별도 입력값과 비교해 차단하던 검사와 작성 기준 금지 표현 검사를 등록 조건에서 제거했다. 기존 상품 대비 설명·상품명 길이 차이도 추가 동의를 요구하지 않는다. AI 초안 작성 지침, 별도 소재·사이즈 필수 입력, 사진 배치 확인, 최종 검수와 입력 길이 상한은 유지한다. 저장된 과거 길이 경고는 조회할 때 현재 조건으로 계산해 표시하지 않는다.

추가 검사 3개: 짧은/긴 문구에 실버·치수·인증·작성 기준 제외 단어가 있어도 검수와 등록 요청이 성공하고 원문이 유지되는지, 상세 설명에 소재·사이즈를 써도 별도 필수 입력란의 공백을 대신하지 않는지 확인했다. 기존 경고가 저장된 상품의 단건/목록 조회에서도 길이 경고가 사라지는지 확인했다. 전체 36개 통과, PostgreSQL 전용 2개는 이번 실행에서 생략했다. Next.js production build 통과. 실행 중인 로컬 작업실을 갱신한 뒤 실제 저장 상품의 필수 확인은 비어 있고 제품 사진 영역 1곳의 빈 배치 안내만 남는지 읽기 조회로 확인했고, 상품 내용·수정 번호·검수 상태는 변경하지 않았다. 이번 변경은 브라우저 조작 없이 API와 빌드로 검증했다.


## Codex 구독 연결 검증

기본 AI 공급자를 Codex CLI로 변경했다. ChatGPT 로그인 여부를 확인하고, 실행 시 구독 인증을 강제한다. 자식 프로세스에는 API 키·앱 비밀정보·대체 API 주소를 넘기지 않으며 유료 API로 자동 전환하지 않는다. 임시 작업 폴더에서 사진을 직접 첨부하고 JSON 스키마 결과를 검증한다. 개인 실행 설정은 불러오지 않고 셸·웹 검색·다중 에이전트 기능은 끈다. 입력과 결과 임시 파일은 성공·실패·시간 초과 후 삭제한다.

추가 자동 검사 8개로 사진·스키마 전달과 구독 인증 설정, API 로그인 거부, 한도 응답 시 API 전환 금지, 잘못된 결과 거부, 시간 초과 종료·정리, 외부 이미지 URL 거부, 상품 문구를 한도 오류로 오인하지 않는 처리, 작업 보관·재시작·수동 입력 보존을 확인했다. 50개 통과, PostgreSQL 전용 2개 생략. Next.js production build와 TypeScript 검사 통과.

설치된 Codex CLI 0.153.4와 실제 ChatGPT 로그인으로 사용자 상품 사진 1장 분석에 성공했다. 별도의 메모리 DB에서 사진 2장 업로드 → 실제 Codex 분류 → 선택된 형식으로 실제 초안 작성 → 미리보기 생성 → 필수 입력 대기까지 확인했다. 두 사진은 목걸이로 분석되었고 기존 사용자 상품의 내용·사진·검수·등록 상태는 바꾸지 않았다. 실쇼핑몰에 상품을 생성하지 않았다.

실행 중인 로컬 작업실에 Codex를 적용했다. 브라우저의 운영 설정에서 ‘AI 연결 확인’을 눌러 ‘ChatGPT 구독 로그인 확인됨’을 확인하고 화면 배치를 점검했다. 한도 초과는 가짜 CLI로 재현했으며 실제 구독을 소진시키지는 않았다. Next.js 사진 요청 버퍼 한도는 110MB로 조정했으나 실제 최대 20장×5MB 업로드 검증은 남아 있다.
