# 실제 상품 등록 연결 준비

현재 작업실은 체험 모드입니다. 화면에서 체험 등록을 완료해도 카페24에 상품이 생성되지 않습니다. 실상품 사진의 Codex 구독 분석은 확인했습니다. 2026-09-11에 별도 로컬 시험 환경에서 실제 카페24 OAuth 연결과 비공개 상품 1개 등록을 확인했습니다. 일반 작업실 화면의 실제 등록 연결 및 운영용 외부 저장소는 아직 검증하지 않았습니다.

## 운영자가 준비할 것

1. **카페24 개발자 앱**: 개발자 가입과 ‘엣더룸 상품등록 자동화’ 앱 생성은 완료했습니다. 실제 연결에는 쇼핑몰 ID, Client ID, Client Secret과 승인 후 돌아올 주소가 필요합니다. 운영자 승인으로 별도 시험 환경의 쇼핑몰 연결을 완료했습니다. 일반 작업실의 운영 연결은 별도로 구성해야 합니다. [카페24 공식 OAuth 안내](https://developers.cafe24.com/app/front/app/develop/oauth)
2. **Codex 구독 로그인**: 현재 맥의 ChatGPT 로그인으로 사진 분석·초안 작성이 실행됩니다. 별도 API 키는 필요하지 않습니다. [Codex 구독 연결 안내](Codex-구독-연결.md)
3. **실제 상품 표본**: 쇼핑몰의 최근 상품에서 사진 순서, 상품 설명, 소재·사이즈, 배송 및 교환/반품 안내를 비교할 수 있어야 합니다. 체험용 안내 문구는 실제 정책으로 사용하지 않습니다.

비밀 키를 채팅이나 GitHub에 붙여넣지 마세요. 준비가 되면 로컬의 Git 제외 설정 파일 또는 배포 서버의 비밀 설정에 입력합니다. 공개해도 되는 정보인 쇼핑몰 ID와 앱 준비 여부부터 확인하면 됩니다.

## 연결을 담당하는 사람이 할 것

- 사용자는 유료 서버 대신 맥에서 실행하고 Codex 구독을 사용하는 방식을 선택했습니다. Railway는 개설하지 않았습니다. 시험에서는 OAuth 반환 경로만 무료 임시 HTTPS 터널에 노출했습니다. 지속적으로 사용할 주소와 작업실의 운영 인증 설정은 다음 단계입니다.
- 현재 체험 데이터를 보존하고, 실제 운영에는 별도의 데이터베이스와 사진 저장소를 사용합니다. 체험 데이터에 실제 연결 키만 넣어 운영 모드로 바꾸지 않습니다.
- HTTPS 작업실 주소와 승인 반환 주소를 확정합니다. 이 앱의 반환 경로는 `/api/cafe24/callback`입니다. 실제 주소는 배포할 서버를 정한 뒤 앱 등록 정보와 동일하게 맞춥니다.
- 이 앱이 요청하는 상품 조회·수정, 분류 조회 및 가격 설정 조회 권한을 확인합니다. 현재 요청 범위는 `mall.read_product`, `mall.write_product`, `mall.read_category`, `mall.read_store`입니다. 상점 조회 권한은 상품 등록 전 가격 계산 기준을 확인하는 데 필요합니다.
- PostgreSQL, S3 또는 R2, 운영자 로그인과 연결 정보 암호화 키를 설정합니다. 설정 이름과 실행 방법은 상위 README 및 `backend/.env.example`에 있습니다.
- 실제 연결 설정에서 `DEMO_MODE=false`를 사용합니다. 체험 모드에서는 실제 카페24 연결·전송을 차단하도록 구현되어 있습니다.

## 실제 사용 전 확인 순서

1. 카페24 연결 승인을 완료합니다.
2. 최근 생성한 상품을 분석하고, 추출한 형식을 실제 상세페이지와 비교합니다.
3. 운영자가 형식을 승인합니다.
4. 시험 상품 한 개로 실제 AI 사진 분류와 설명을 확인합니다. 가격·소재·치수는 확인된 값만 입력합니다.
5. 미리보기와 실제 정보를 검수한 다음, **진열 안 함·판매 안 함** 상태로 한 개를 등록합니다.
6. 카페24 관리자에서 대표·추가 사진, 상세페이지 순서, 금액, 분류, 검색 정보를 확인합니다.
7. 실제 연결 환경에서 연결 갱신과 실패 후 재시도를 확인한 뒤 운영을 시작합니다.

코드 검사나 체험 등록 성공만으로 이 절차가 완료된 것으로 간주하지 않습니다.

## 실제 시험에서 확인한 사항 (2026-09-11)

- 같은 시험 상품에 실패한 단계만 재시도하여 대표 사진, 추가 사진 8장, 상세페이지 사진 9장, 가격·분류·SEO를 등록했습니다. 진열과 판매는 모두 꺼져 있음을 API와 관리자 화면에서 확인했습니다.
- POST/PUT 요청의 쿼리 문자열 제거, 이미지 업로드의 `requests` 배열, 대표 사진의 Base64 데이터 URL을 실제 API 규격에 맞게 수정했습니다. 대표 사진 응답이 201이어도 이미지 주소가 비어 있으면 완료로 처리하지 않습니다.
- 가격 설정 조회 권한과 `calculate_price_based_on` 필드명을 보완했습니다. 권한 변경 직후에는 인증 서버에 반영될 시간이 필요했고, 이후 운영자 권한 재동의를 마쳤습니다.
- 시험 연결정보와 결과는 Git에서 제외한 로컬 저장소에 보관했습니다. 임시 터널 및 시험용 연결 도구는 상시 운영 배포가 아닙니다.
- 운영자 요청으로 자동 배송·교환/반품 안내 문구를 제거했습니다. 운영자가 추후 별도 안내 사진을 직접 넣습니다. 사진마다 네 줄(24px 줄간격, 총 96px)의 간격을 둡니다. 현재 일반 작업실의 체험 등록 상태는 실제 등록 상태로 변경하지 않았습니다.
